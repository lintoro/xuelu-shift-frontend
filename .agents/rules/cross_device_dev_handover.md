# 異地跨電腦開發每日收工同步作業規則 (Cross-Device Dev Handover Policy)

## 核心觸發情境
當使用者表達以下或類似語意時：
- 「本日開發完成」
- 「今天先做到這裡」
- 「準備換到另一台電腦」
- 「準備離開這台電腦」
- 「今天收工 / 下班」

## 標準作業 SOP (Strict Order of Operations)

### 第一步：主動確認（未經命令不得擅自執行）
當收到上述相關語意時，**必須先主動詢問使用者**：
> 「收到！檢測到您準備結束當前電腦的開發進度。請問是否現在為您執行【異地開發收工同步作業】（包含 git status 檢查、git add .、自動提交並 push 至 GitHub）？」

### 第二步：等待命令後執行
**必須嚴格等待使用者下達執行命令（例如「是」、「好」、「執行」）後，才在終端機依序執行以下指令**：

```bash
# 1. 檢查有修改的檔案
git status

# 2. 將修改全數加入暫存區
git add .

# 3. 提交進度備註
git commit -m "feat: 今日進度完成，準備切換至另一台電腦"

# 4. 推送到 GitHub
git push origin main
```

### 第三步：完成後回報與換機提醒
執行完畢後，向使用者確認推送結果，並友善提醒：
- 「遠端 GitHub 與 Vercel 線上正式站已同步至最新進度。」
- 「當您切換至另一台新電腦（例如家中或筆電）時，只需在該電腦開啟專案並執行 `git pull origin main`，即可無縫接續開發！」
