# 異地跨電腦開發雙向同步作業規則 (Cross-Device Dev Handover Policy)

## 一、開工同步守則 (Handover In - 換機開啟專案)

### 1. 核心觸發情境
每當在新對話會話開始、使用者打招呼、開啟新工作或表達以下語意時：
- 「開始開發」
- 「我剛換到這台電腦」
- 「今天開始」
- 任何新對話的第一個任務指示

### 2. AI 開工主動偵測與提醒防護
AI 在評估或執行任何修改前，應先檢視本地 Git 與遠端同步狀態：
- 若偵測到本地落後遠端（Behind origin/main），**必須在回覆第一時間主動提醒使用者**：
  > 「⚠️ **偵測到雲端 GitHub 有更新進度（落後遠端 N 個 Commit）**，可能來自您在另一台電腦上的推送。建議先執行同步拉取，以避免程式碼衝突。請問是否立即為您執行 `git pull origin main`？」
- 經使用者同意或命令後，執行 `git pull origin main`（若有 package.json 變更則自動補齊 `npm install`）。

---

## 二、收工同步守則 (Handover Out - 當前電腦結束)

### 1. 核心觸發情境
當使用者表達以下或類似語意時：
- 「本日開發完成」
- 「今天先做到這裡」
- 「準備換到另一台電腦」
- 「準備離開這台電腦」
- 「今天收工 / 下班」

### 2. 標準作業 SOP (Strict Order of Operations)

#### 第一步：主動確認（未經命令不得擅自執行）
當收到上述相關語意時，**必須先主動詢問使用者**：
> 「收到！檢測到您準備結束當前電腦的開發進度。請問是否現在為您執行【異地開發收工同步作業】（包含 git status 檢查、git add .、自動提交並 push 至 GitHub）？」

#### 第二步：等待命令後執行
**必須嚴格等待使用者下達執行命令（例如「是」、「好」、「執行」、「請上推」）後，才在終端機依序執行以下指令**：

```bash
# 1. 檢查有修改的檔案
git status

# 2. 將修改全數加入暫存區
git add .

# 3. 提交進度備註
git commit -m "feat: 今日進度完成，準備切換至另一台電腦"

# 4. 推送到 GitHub
git push origin main
```

#### 第三步：完成後回報與換機提醒
執行完畢後，向使用者確認推送結果，並友善提醒：
- 「遠端 GitHub 與 Vercel 線上正式站已同步至最新進度。」
- 「當您切換至另一台電腦時，直接在終端機執行 `npm run sync`（或雙擊 `sync.bat`），即可秒速同步最新進度並無縫接續開發！」
